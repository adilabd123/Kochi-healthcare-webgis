# S3 — Measuring Walking Access

## Network vs straight-line distance
A straight-line ("Euclidean" or "as the crow flies") buffer assumes a person can walk through buildings, walls, railway lines and canals. Real pedestrians follow streets and footpaths, so the true walking distance is always at least as long and usually 20–40 % longer in a city. The ratio of the two is the *circuity* or *detour factor*. In Kochi, the Seaport–Airport Road, the railway line near Kaloor/Edappally and the NH 66 bypass all add detours, because people can only cross them at certain points. A 1.2 km circular buffer therefore **over-states** access, and the error is largest exactly where barriers exist.

```
   Clinic C                      straight line  C ----------- H   = 1.2 km
     |                           network path   C--+
     +-----+    railway / canal                    |
           |  ================                     +-----+ (bridge)
           +-----------+-----                            |
                       |                                 +---- H  = 1.6 km
                       H  Home                  detour factor = 1.6 / 1.2 = 1.33
```

## Walking isochrones
An isochrone is the area reachable within a fixed travel *time*. To build one, load the street network (OSM ways tagged for walking) into pgRouting, snap the facility to its nearest node, and run a shortest-path search (`pgr_drivingDistance`) with edge cost = length ÷ walking speed. Then wrap the reached nodes or edges in a polygon, using a concave hull or a small buffer around the reached edges. The shape is irregular, stretched along main roads and pinched at barriers, and that is the point: it shows what a circle hides.

## Walking-speed assumptions
Our urban threshold is **15 minutes at 4.8 km/h ≈ 1.2 km** (1.33 m/s), a common planning default for healthy adults. Older adults, people with disabilities and caregivers with small children walk more slowly. The sensitivity run uses **3.6 km/h (1.0 m/s)**. You can read the same speed two ways:
- *same time, shorter reach*: in 15 minutes an elderly person covers only **0.9 km**;
- *same distance, longer time*: covering 1.2 km takes them **20 minutes**.

Reporting both makes clear that "covered" population depends on *who* is walking. Heat, rain, broken footpaths and crossing waits also slow real walks, so every result should state its speed assumption.

## The Modifiable Areal Unit Problem (MAUP)
When point-level reality (people, clinics) is summarised into zones, the result depends on how the zones are drawn. MAUP has two parts. The **scale effect**: the same data aggregated to wards, then to H3 res 9 cells, gives different averages and correlations. The **zoning effect**: at the same scale, shifting the boundaries changes the result. A ward may look "well served" because one large hospital sits inside it, while half its residents live more than 1.2 km away. Mitigations: compute access at the finest unit available (buildings or small H3 cells), compare results across two or more unit systems (wards vs H3), and report that comparison instead of a single number.
