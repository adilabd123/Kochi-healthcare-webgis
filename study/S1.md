# S1 — OGC Web Services, Axis Order and CRS Distortion

## WMS 1.1.1 vs 1.3.0: the EPSG:4326 axis flip
A Web Map Service returns a *picture* of the data (PNG/JPEG) for a bounding box. Version 1.1.1 always reads coordinates as x,y = longitude,latitude. Version 1.3.0 instead follows the axis order the EPSG registry defines for each CRS, and EPSG:4326 is officially defined as **latitude first**. So the same request for our Kochi wards must swap its numbers when you change version. The parameter name also changes, from `SRS=` to `CRS=`. If you want lon/lat in 1.3.0, ask for `CRS=CRS:84`, which is the same datum with the axes in x,y order. A blank or misplaced map from a 1.3.0 request is almost always this axis flip.

```
                 parameter        BBOX order                   Kochi study area
WMS 1.1.1   SRS=EPSG:4326   minLon,minLat,maxLon,maxLat   76.28,9.98,76.33,10.04
WMS 1.3.0   CRS=EPSG:4326   minLat,minLon,maxLat,maxLon   9.98,76.28,10.04,76.33
WMS 1.3.0   CRS=CRS:84      minLon,minLat,maxLon,maxLat   76.28,9.98,76.33,10.04
WMS (any)   EPSG:32643      minE,minN,maxE,maxN           (metres, no ambiguity)
```

## WFS 2.0 and filters
A Web Feature Service returns the *features themselves* (GML or GeoJSON) so the client can query, style or analyse them. WFS 2.0 uses `typeNames`, `count` and `startIndex` (for paging), plus `srsName`. Filtering follows the OGC Filter Encoding 2.0 standard. It covers comparison operators (`PropertyIsEqualTo`, `PropertyIsLike`), spatial operators (`BBOX`, `Intersects`, `Within`, `DWithin`) and logical `And`/`Or`/`Not`. GeoServer also accepts the shorter `CQL_FILTER` vendor parameter, e.g. `CQL_FILTER=category='hospital' AND BBOX(geom,76.28,9.98,76.33,10.04)`. Axis order bites here too: GML output in WFS 1.1/2.0 with EPSG:4326 is lat/lon, while GeoJSON is always lon/lat.

## WCS
A Web Coverage Service serves rasters (*coverages*) with their real cell values, not a rendered picture. A population grid or DEM comes back as a GeoTIFF you can compute with. The operations are `GetCapabilities`, `DescribeCoverage` and `GetCoverage`. WCS 2.0 trims the raster with `subset=Lat(9.98,10.04)&subset=Long(76.28,76.33)`.

## OGC API – Features
This is the modern, RESTful successor to WFS. Every resource is a URL (`/collections`, `/collections/{id}/items?bbox=...&limit=50`), JSON/GeoJSON is the default format, and the default CRS is CRS84 (lon/lat), which removes most of the axis confusion. Part 2 adds other CRSs and Part 3 adds CQL2 filtering. `pg_featureserv` implements it directly on PostGIS tables.

## EPSG:4326 vs 3857 vs UTM 43N: area distortion
EPSG:4326 is angular, not a projection: `ST_Area` on `geometry(4326)` returns *square degrees*, which mean nothing as an area. At 10°N one degree of longitude is about 109.6 km but one degree of latitude is about 110.6 km. Web Mercator (EPSG:3857) is conformal, so its scale grows by 1/cos(latitude). At Kochi that inflates areas by about **3.1 %** (sec²10° ≈ 1.031). The inflation is small here but grows quickly toward the poles. UTM Zone 43N (EPSG:32643, central meridian 75°E) has scale ≈ 0.99985 at 76.3°E, so area error is about **0.03 %**. Rule for this project: store in 4326 (or `geography`), display in 3857, and measure every distance, buffer and area in 32643.
